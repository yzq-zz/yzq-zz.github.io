ZGC · 并发回收 + good_color 状态机

经典单代 ZGC · 3 个 STW · 核心：good_color 全局切换 + 堆内指针惰性修复 · by yzq
全局 good_color 状态机
Remapped = 已对齐当前视图（地址有效）
M0 = 本轮标记色 / 旧标记残留
M1 = 交替轮次标记色
红色虚线 = 指针颜色 ≠ good_color，barrier 会拦截
root 引用 活引用（颜色=good_color） 指针颜色≠good_color（待修复） 新地址引用

特写：Load Barrier slow_path —— 不管对象搬没搬，颜色都要变 Remapped

① Z.ref 字段（修复前）
z.ref: A@R1 [M0]
Z 在 R2，它的 ref 指向 A 的旧地址 R1。
当前 good_color = Remapped
颜色 M0 ≠ Remapped → barrier 拦截
② slow_path 逻辑
slow_path(ptr)
  old = ptr 去色 → R1
  查 forwarding table:
    R1 → R6 ✓ 找到
  新指针 = R6 | Remapped
  CAS 写回字段 ✓
③ 修复后
z.ref: A@R6 [Remapped]
关键：对象 被搬走时，地址也改。
对象 没被搬时，只改颜色。
共同结果：颜色都变成 Remapped。
结果：调用方拿到 A@R6 [Remapped]，正常访问。下次再读 z.ref → M0 ≠ Remapped？再修一次。下次 barrier 命中时直接放行。

ZGC 核心概念（始终可见）

染色指针（Colored Pointers）

64 位指针的低几位存 GC 元数据（颜色位）。x86-64 实际只用 48 位寻址，ZGC 借走高几位存状态。

  • M0 / M1：标记色，交替使用区分轮次
  • Remapped：指针已对齐当前视图，地址有效
  • 好处：barrier 只看指针一眼就知道要不要处理，不查对象头

good_color 全局切换

good_color 是全局单一变量，每次 STW 切换。所有指针瞬间"wrong"，但指针本身不动。

  • 切换 = O(1) 写，不动堆里任何指针
  • 旋转：M0 → Rm → M1 → Rm → ...
  • 错误颜色靠 barrier 逐槽修正，GC 并发做

Load Barrier 工作方式

ref = *fieldAddr
if (colorBits(ref) ≠ good_color) {
  ref = slow_path(fieldAddr, ref);
}
use(ref); // fast path 直接用

fast path 只比较颜色位（寄存器操作，几纳秒）。slow path 走并发路径。

slow_path 两件事

old_addr = ref 去色
if forwarding[old_addr] 找到 { 搬了 → addr=新地址 }
else { 没搬 → addr=原地址 }
return addr | 当前 good_color

区别：搬走的改地址+颜色，没搬的只改颜色。共同结果：颜色都变成 good_color。

SATB 写屏障（Snapshot-At-The-Beginning）

并发标记开始时照一张快照。之后应用线程写屏障记录"曾经指向谁"，保证标记不漏。

  • z.ref = null → 写屏障记录"A.ref 曾指向 null"（快照保证 B 仍被标记）
  • 并发标记结束后 STW 排空缓冲
  • 代价：可能多活几个垃圾（下轮回收）
  • 好处：不需要反复扫描保证正确性
