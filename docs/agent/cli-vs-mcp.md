# Agent 面试题

## 1. Agent 通过 CLI 和 MCP 调用工具有什么区别？

**一句话定性：** CLI 是让 Agent「开终端敲命令」——输入是命令行字符串，输出是自由文本；MCP 是让 Agent「调一个标准化的远程函数」——输入输出都是结构化 JSON，工具会「自描述」。

### 1.1 接口契约（最核心区别）

- **CLI**：没有机器可读的契约，Agent 得靠读文档或 `--help` 猜参数怎么拼。参数是拼字符串，容易出现转义、注入问题。
- **MCP**：基于 JSON-RPC 标准协议，每个工具启动时自动暴露名字、功能描述和 JSON Schema 入参，Agent 拿到就知道该传什么字段。参数是结构化对象，不用拼字符串。

### 1.2 状态与生命周期

- **CLI**：一次调用拉起一个进程，执行完就退出，天然无状态；要保持上下文得自己搞临时文件或传 ID。
- **MCP**：Server 是常驻进程，一次连接多次调用，可以维持会话状态、流式推送、订阅变更。

### 1.3 可发现性与生态复用

- **CLI**：能直接复用机器上海量的现成命令行工具（git、kubectl……），零改造成本；但换个 Agent 框架要重新教一遍怎么用。
- **MCP**：「一次开发，到处接入」——同一个 MCP Server 可以被任何兼容 MCP 的客户端（Claude Desktop、Trae、IDE）直接挂载，工具列表自动同步。这就是 MCP 想做「Agent 工具界的 USB-C」的原因。

> **补充：** 实践中很多 MCP Server 底层还是包了一层 CLI 或 HTTP API——MCP 解决的不是「能不能做」，而是**标准化、可靠性和复用性**的问题。
