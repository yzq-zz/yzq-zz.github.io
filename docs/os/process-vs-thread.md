# 进程 vs 线程

进程是操作系统**分配资源**的基本单位，线程是 CPU**调度执行**的基本单位——这是理解两者区别的根本出发点。

## 一、进程被分配了哪些资源

操作系统给每个进程分配的资源主要有四样：

- **独立的内存空间**：每个进程拥有自己的虚拟地址空间，里面装着自己的代码段、数据段、栈、堆。进程之间内存相互隔离，A 看不到 B、也写不了 B。
- **文件描述符**：每打开一个文件 / socket / 管道，进程就拿到一个文件描述符作为"门票"，后续读写全靠它。打开的资源越多，文件描述符表越长。
- **CPU 时间片**：进程轮流使用 CPU 的一小段时间，操作系统负责把 CPU 在不同进程间切来切去并记账。
- **PCB（进程控制块）**：操作系统为每个进程维护一份内核数据结构，记录 PID、状态（运行/就绪/阻塞）、优先级、页表位置、资源表指针等。可以理解为操作系统为这个进程建立的"档案"。

> 一个进程在操作系统眼里，就是"一块独立的内存 + 一组文件描述符 + 一份 CPU 使用资格 + 一份 PCB 档案"。

**内存隔离的具体机制——页表**：每个进程都有自己的页表，负责把虚拟地址映射到物理地址。进程之间的虚拟地址可以相同，但通过各自的页表翻译后指向不同的物理内存，互不干扰。这就是"独立的内存空间"在硬件层面是怎么落地的。

## 二、线程是什么

线程是 CPU 执行的基本单位，线程去抢占 CPU 去执行任务。一个进程里可以有多个线程，线程之间**共享进程分配到的全部资源**——内存、文件描述符、页表这些都共用。线程自己只保留执行相关的最小集合：

- 程序计数器 PC：下一条要执行的指令在哪
- 一组通用寄存器：当前各寄存器的值
- 自己的栈：函数调用一层一层叠起来的地方

可以理解为：进程是"资源容器"，线程是"执行流"。

## 三、为什么进程上下文切换比线程重

两者的差异不在于"线程自己那一小份信息"——这些是必须动的；真正的差异在于切换时还要不要动那些"进程级"的东西。

### 1. 共同动作（两者都要做）

切换时都必须保存和恢复线程自己的轻量信息：程序计数器、寄存器、栈指针。这部分是公共的，量也小。

### 2. 进程切换额外要做**

- **切换页表**：每个进程的虚拟地址到物理地址的映射关系不同（各自的页表），CPU 上有个专门寄存器（x86 上叫 CR3）指向当前页表基址，进程切换时必须换成目标进程的页表基址。
- **TLB 全部失效**：TLB 是 CPU 内部一块极快的缓存，专门用来加速"虚拟地址 → 物理地址"的翻译（因为查页表慢）。问题是 TLB 里缓存的全是旧进程的页表项，换了页表之后这些缓存全部作废，新进程第一次访问内存几乎都会 TLB miss，要再走慢路径查页表。
- **文件描述符表、PCB 等内核信息全换**：操作系统为每个进程维护的内核视角信息（文件表、信号表、记账数据等）都要换成目标进程的版本。

### 3. 线程切换（同进程内）不用做

- 页表不动（共享地址空间，CR3 寄存器值不变，TLB 不用清空）
- 文件描述符表、信号表不动（这些都是进程级的，多个线程共享一套）
- PCB 不动

线程切换只涉及"线程自己的小现场 + 各自的内核栈"，进程级别的所有环境原封不动。

### 4. 一句话总结

> 进程切换要动的东西多（换页表 → TLB 失效 → 缓存冷启动 → 换各种内核表），线程切换只动线程自己的那一小份。所以前者重、后者轻。

::: tip 缓存冷启动
进程切换还涉及到 L1 / L2 / L3 CPU 缓存几乎全部失效（因为新进程访问的内存地址和旧进程完全不同）。新进程哪怕只是执行一行赋值，也要先触发缓存未命中、查一次页表、再去主存取数据——直到缓存重新热起来。这是进程切换实际开销远高于线程切换的关键放大器。
:::

## 四、补充几个区别点

### 崩溃影响

- **线程崩溃 → 整个进程崩**：线程共享进程的资源（尤其是地址空间），崩了会把整个地址空间搞坏。
- **进程之间互不影响**：每个进程资源相互独立，一个进程崩溃不会牵连其他进程。

### 通信方式

**线程通信**（同一进程内，资源天然共享）：

- **直接共享变量**：线程共享堆内存，直接读写同一个变量是最直接的通信方式
- **JDK 同步工具**（用于线程间协调）：
  - `CountDownLatch`：适用于主线程等待子线程全部执行完的场景
  - `Semaphore`：用来控制同时允许多多少线程访问某东西

**进程通信**（进程间资源隔离，必须走 OS 提供的机制）：

- **管道**：单向字节流，常见于父子进程或 shell 场景
- **消息队列**：典型场景是生产者-消费者模型，生产者进程往消息队列写数据，消费者进程从消息队列读数据，通过中间的队列解耦

> 进程通信 vs 线程通信的核心区别：线程共享内存所以通信便宜但要同步，进程资源隔离所以必须靠 OS 机制通信，慢一点但天然安全。

## 踩坑记录

- 把"线程崩溃 → 进程崩"理解成"线程崩了线程自己完事"——共享地址空间意味着线程的崩溃会污染整个进程
- 以为进程间通信和线程间通信一样可以直接共享变量——不行，进程内存隔离，必须走管道 / 消息队列等机制
- 把 Semaphore 当成单纯的"线程通信"——严格说它是同步工具，用来控制并发访问数，但能起到线程间协调的作用
